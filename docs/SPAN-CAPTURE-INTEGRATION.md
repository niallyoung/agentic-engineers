# Span Capture Integration (Agents-Only, No External Scripts)

## Architecture

Span capture is **built into agent SKILLS**, not external utilities:

1. **Orchestrator SKILL:** Captures spans when receiving HANDBACKs from agents
2. **Model Engineer SKILL:** Generates `artifacts/index.json` as part of feedback analysis
3. **Agents:** Continue normal workflow (receive DELEGATE → execute → return HANDBACK with token counts)

**No external Python scripts, no Makefile targets — only AGENTS with enhanced SKILLS.**

---

## Orchestrator Span Capture (SKILL)

When Orchestrator receives HANDBACK from an agent:

```
Orchestrator receives HANDBACK
  ├─ Extract from HANDBACK:
  │  ├─ task_id
  │  ├─ agent_role (e.g., "Engineer", "Senior Engineer")
  │  ├─ agent_model (e.g., "claude-haiku-4.5")
  │  ├─ status (complete, blocked, partial)
  │  ├─ tokens_in (input tokens)
  │  ├─ tokens_out (output tokens)
  │  └─ decision (PASS, FAIL, ESCALATE, etc.)
  │
  ├─ Calculate span attributes:
  │  ├─ duration_ms = end_time - start_time
  │  ├─ cost_usd = (tokens_in × input_price + tokens_out × output_price)
  │  ├─ total_tokens = tokens_in + tokens_out
  │  └─ trace_id (generated at start, reused across parallel agents)
  │
  ├─ Create SPAN YAML with custom span schema:
  │  ├─ trace_id, span_id, parent_span_id
  │  ├─ span_name (e.g., "agent.engineer.execution")
  │  ├─ start_time, end_time, duration_ms
  │  ├─ status (success/error/deadline_exceeded)
  │  └─ attributes (agent_type, agent_model, service_name, tokens, cost, decision, etc.)
  │
  └─ Write SPAN file to: artifacts/2026-MM-DD/SPAN-{timestamp}-{agent_type}.yaml
```

**Implementation:** This is added to Orchestrator's HANDBACK processing in Phase 6 code (not part of Phase 5.10 spec).

## Model Engineer Artifact Index (SKILL)

Model Engineer's workflow includes generating `artifacts/index.json`:

```
Model Engineer receives: ~10-100 completed task HANDBACKs
  │
  ├─ 1. Analyze feedback (existing behavior)
  │  ├─ Which models succeeded?
  │  ├─ Which failed?
  │  └─ Token efficiency patterns
  │
  ├─ 2. Generate ranking (existing behavior)
  │  └─ Rank 1/2/3 recommendations for next similar task
  │
  └─ 3. NEW: Artifact Indexing (index generation)
     ├─ Scan artifacts/2026-*/
     ├─ Extract metadata from DELEGATE/HANDBACK/SPAN files
     ├─ Create index by: file_type, task_id, agent_type, status
     ├─ Calculate stats: total_tokens, total_cost, critical_issues, escalations
     └─ Write to: artifacts/index.json
```

**Benefit:** Model Engineer already reads artifacts for feedback; generating index is natural extension.

## Data Flow: No External Tools

```
Orchestrator (agent) writes SPAN
  ↓
artifacts/2026-MM-DD/SPAN-{timestamp}-{agent_type}.yaml created
  ↓
  (existing artifacts: DELEGATEs, HANDBACKs already written)
  ↓
Model Engineer (agent) runs periodically (as part of feedback loop)
  ├─ Reads: artifacts/2026-*/, ~/.agentic-engineers/artifacts/queue/
  ├─ Extracts: task_id, status, tokens, cost, severity, decision
  ├─ Generates: artifacts/index.json
  └─ Uses: Index to analyze cost trends, model selection patterns
```

**No external scripts. Everything flows through agent execution.**

## Span Format (Custom span schema)

Orchestrator writes spans in `artifacts/2026-MM-DD/SPAN-{timestamp}-{agent_type}.yaml`:

```yaml
---
# Structured span record (written by Orchestrator)
trace_id: "abc123def456ghi789jkl"
  # Unique per quality-gate workflow; reused for parallel agents
span_id: "engineer-2026-05-02-fix-timeout"
  # Unique per agent invocation
parent_span_id: "orchestrator-quality-gate"
  # Links to parent Orchestrator span
span_name: "agent.engineer.execution"
  # Format: agent.{role}.execution

start_time: "2026-05-02T10:00:15Z"
  # When DELEGATE was sent
end_time: "2026-05-02T10:03:45Z"
  # When HANDBACK was received
duration_ms: 210000
  # Milliseconds elapsed

status: "success"
  # success | error | deadline_exceeded

attributes:
  # Agent Identity
  agent_type: "engineer"
  agent_model: "claude-haiku-4.5"
  agent_role: "Engineer"
  
  # Resource
  service_name: "{example-service}"
  service_commit_sha: "abc123def..."
  
  # Token Usage (from HANDBACK)
  input_tokens: 1200
  output_tokens: 950
  total_tokens: 2150
  cost_usd: 0.0645  # calculated: (1200 × 0.000080 + 950 × 0.000240)
  
  # Quality
  findings_count: 0
  severity: "PASS"
  confidence: 0.95
  
  # Decision
  decision: "PASS"
  recommended_action: "proceed"
  
  # Structured span record status
  status_code: 0  # 0=Ok, 1=Error, 2=Deadline_Exceeded
  status_description: ""
```

## Index Format (Generated by Model Engineer)

Model Engineer writes `artifacts/index.json` (example structure):

```json
{
  "generated_at": "2026-05-02T10:30:00Z",
  "total_artifacts": 45,
  "by_file_type": {
    "DELEGATE": [...],
    "HANDBACK": [...],
    "SPAN": [...]
  },
  "by_task_id": {
    "2026-05-02-fix-timeout": [...],
    "2026-05-02-add-feature": [...]
  },
  "by_agent_type": {
    "engineer": [...],
    "senior-engineer": [...],
    "quality-engineer": [...]
  },
  "by_status": {
    "complete": [...],
    "blocked": [...]
  },
  "stats": {
    "total_tokens": 245000,
    "total_cost_usd": 7.35,
    "critical_issues": 0,
    "escalations": 2
  }
}
```

**Purpose:** Enables Model Engineer to query cost patterns, analyze which agents consumed most tokens, identify escalation trends.

## Pricing (Model Engineer Calculation)

When calculating cost in span attributes, use model-specific pricing:

| Model | Input Price | Output Price |
|-------|-------------|--------------|
| claude-haiku-4.5 | $0.000001/token | $0.000005/token |
| claude-sonnet-5 | $0.000003/token | $0.000015/token |
| claude-opus-5 | $0.000005/token | $0.000025/token |
| claude-fable-5 | $0.000010/token | $0.000050/token |

**Formula:** `cost_usd = (input_tokens × input_price) + (output_tokens × output_price)`

## Key Principles

1. **No external scripts** — all functionality is agent SKILLS
2. **DELEGATE/HANDBACK untouched** — agents don't need to know about spans
3. **Orchestrator writes spans** — observability is harness responsibility
4. **Model Engineer owns index** — cost analysis is feedback loop responsibility
5. **Custom span format** — structured records for consistent observability
