# Prometheus Exporter Integration Guide

## Overview

The PrometheusExporter exports token and cost metrics in Prometheus text format for integration with Prometheus and Grafana monitoring systems.

## Token Metrics

Token metrics track Claude API token consumption across different dimensions:

### Token Counters by Role

- **`orchestrator_tokens_input_by_role`** - Input tokens consumed by each role
  - Labels: `role` (engineer, senior_engineer, orchestrator, etc.)
  - Type: Counter
  - Example: `orchestrator_tokens_input_by_role{role="engineer"} 50000`

- **`orchestrator_tokens_output_by_role`** - Output tokens generated by each role
  - Labels: `role`
  - Type: Counter

- **`orchestrator_tokens_cached_by_role`** - Cached tokens read by each role
  - Labels: `role`
  - Type: Counter

### Token Counters by Model

- **`orchestrator_tokens_input_by_model`** - Input tokens consumed by each model
  - Labels: `model` (claude-haiku-4-5, claude-sonnet-4-6, claude-opus-4-7)
  - Type: Counter

- **`orchestrator_tokens_output_by_model`** - Output tokens generated by each model
  - Labels: `model`
  - Type: Counter

### Token Distribution Histogram

- **`orchestrator_tokens_per_task`** - Distribution of total tokens consumed per task
  - Buckets: [100, 500, 1000, 5000, 10000, 50000, 100000]
  - Type: Histogram
  - Provides: `_bucket`, `_sum`, `_count` suffixes

## Cost Metrics

Cost metrics track USD costs across different dimensions:

### Cost Counters by Role

- **`orchestrator_cost_usd_by_role`** - Total cost by role
  - Labels: `role`
  - Type: Counter
  - Example: `orchestrator_cost_usd_by_role{role="engineer"} 0.50`

### Cost Counters by Model

- **`orchestrator_cost_usd_by_model`** - Total cost by model
  - Labels: `model`
  - Type: Counter
  - Example: `orchestrator_cost_usd_by_model{model="claude-haiku-4-5"} 0.30`

### Cost Counters by Task Type

- **`orchestrator_cost_usd_by_task_type`** - Total cost by task type
  - Labels: `task_type` (code_review, bug_fix, documentation, refactoring, etc.)
  - Type: Counter
  - Example: `orchestrator_cost_usd_by_task_type{task_type="code_review"} 0.75`

### Daily Cost Gauge

- **`orchestrator_cost_usd_daily`** - Daily cost aggregation
  - Labels: `date` (YYYY-MM-DD format)
  - Type: Gauge
  - Example: `orchestrator_cost_usd_daily{date="2026-05-17"} 2.50`

### Cost Distribution Histogram

- **`orchestrator_cost_per_task`** - Distribution of cost per task
  - Buckets: [0.001, 0.01, 0.05, 0.1, 0.5, 1.0, 5.0, 10.0]
  - Type: Histogram

### Cost Efficiency Metric

- **`orchestrator_cost_per_quality_point`** - Cost per quality point achieved
  - Buckets: [0.0001, 0.0005, 0.001, 0.005, 0.01, 0.05, 0.1]
  - Type: Histogram
  - Measures: Cost efficiency of task execution

## Usage Examples

### Basic Export

```python
from src.orchestration.monitoring.metrics import MetricsRegistry, create_orchestrator_metrics
from src.orchestration.monitoring.prometheus_exporter import PrometheusExporter

# Create registry
registry = MetricsRegistry()
metrics = create_orchestrator_metrics(registry)

# Populate metrics
metrics["tokens_total"].inc(1000)
metrics["cost_usd_total"].inc(0.50)

# Export to Prometheus format
exporter = PrometheusExporter(registry)
text = exporter.export()
print(text)
```

### Export Token Metrics with Labels

```python
from src.orchestration.monitoring.metrics import MetricsRegistry, create_token_metrics
from src.orchestration.monitoring.prometheus_exporter import PrometheusExporter

registry = MetricsRegistry()
token_metrics = create_token_metrics(registry)

# Add token metrics by role
tokens_by_role = registry.counter(
    "orchestrator_tokens_input_by_role",
    "Input tokens by role",
    labels={"role": "engineer"}
)
tokens_by_role.inc(50000)

# Export
exporter = PrometheusExporter(registry)
output = exporter.export()
```

### Export Cost Metrics with Multiple Dimensions

```python
from src.orchestration.monitoring.metrics import MetricsRegistry, create_cost_metrics
from src.orchestration.monitoring.prometheus_exporter import PrometheusExporter

registry = MetricsRegistry()
cost_metrics = create_cost_metrics(registry)

# Cost by role
registry.counter(
    "orchestrator_cost_usd_by_role",
    labels={"role": "engineer"}
).inc(0.50)

# Cost by model
registry.counter(
    "orchestrator_cost_usd_by_model",
    labels={"model": "claude-haiku-4-5"}
).inc(0.30)

# Cost by task type
registry.counter(
    "orchestrator_cost_usd_by_task_type",
    labels={"task_type": "code_review"}
).inc(0.75)

# Export
exporter = PrometheusExporter(registry)
output = exporter.export()
```

### Export to File

```python
exporter = PrometheusExporter(registry)
exporter.export_to_file("/metrics/prometheus.txt")
```

## Prometheus Format

The exporter generates standard Prometheus exposition format (text/plain; version=0.0.4):

```
# HELP metric_name Description of metric
# TYPE metric_name metric_type
metric_name{label1="value1",label2="value2"} 42.0
```

### Metric Types

- **Counter**: Monotonically increasing value
- **Gauge**: Value that can increase or decrease
- **Histogram**: Distribution with buckets, sum, and count

### Label Format

Labels are formatted as comma-separated key="value" pairs within curly braces:

```
metric_name{role="engineer",model="haiku"} 1000
```

Labels are sorted alphabetically by key for consistency.

## Integration with Grafana

### Prometheus Data Source Configuration

1. Add Prometheus data source in Grafana
2. Configure scrape endpoint: `http://orchestrator:8080/metrics`
3. Set scrape interval: 15s (or as needed)

### Example Grafana Queries

**Total tokens by role:**
```promql
sum by (role) (orchestrator_tokens_input_by_role)
```

**Cost by model:**
```promql
sum by (model) (orchestrator_cost_usd_by_model)
```

**Cost per task distribution (p95):**
```promql
histogram_quantile(0.95, orchestrator_cost_per_task)
```

**Daily cost trend:**
```promql
orchestrator_cost_usd_daily
```

## Prometheus Scrape Configuration

Add to `prometheus.yml`:

```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'agentic-engineers'
    static_configs:
      - targets: ['localhost:8080']
    metrics_path: '/metrics'
```

## Thread Safety

All metrics are thread-safe:
- Counters use locks for atomic increments
- Gauges use locks for atomic updates
- Histograms use locks for bucket updates

Safe for concurrent updates from multiple agents.

## Performance Characteristics

- Export time: <5ms for typical metric sets
- Memory overhead: ~100 bytes per metric
- Label cardinality: Unlimited (Prometheus handles high cardinality)

## Best Practices

1. **Use consistent label values** - Avoid high cardinality labels
2. **Aggregate before export** - Combine similar metrics
3. **Set appropriate buckets** - Match your expected value ranges
4. **Monitor metric growth** - Watch for cardinality explosion
5. **Use descriptive names** - Follow Prometheus naming conventions

## Troubleshooting

### Metrics not appearing in Prometheus

1. Verify exporter is running and accessible
2. Check Prometheus scrape logs
3. Verify metric names follow Prometheus conventions
4. Check label values don't have invalid characters

### High cardinality warnings

1. Review label values for unbounded growth
2. Aggregate similar labels
3. Use relabeling in Prometheus config

### Performance issues

1. Check number of unique metric/label combinations
2. Reduce scrape frequency if needed
3. Use Prometheus remote storage for long-term retention
