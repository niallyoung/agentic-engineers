## Auto-Generated Files

Each subdirectory contains an **`INTEGRATION-SUMMARY.md`** file that is automatically generated by the `harness-integration-tracker` skill. These files track:

- **KNOWN_KEYS**: Configuration keys supported by the harness
- **KNOWN_MODELS**: Models supported and tested with this harness
- **VERSION HISTORY**: Breaking changes, new capabilities per version
- **DRIFT DETECTION**: Differences between docs/ and actual integration code
- **LAST UPDATED**: Timestamp of most recent scan

To regenerate summaries, run:

```bash
python3 src/skills/harness-integration-tracker/scripts/harness_integration_tracker.py
```

## Maintenance

### Adding New Harness Documentation

1. Create new subdirectory: `docs/research/{harness}-docs/`
2. Add research files (naming convention: `{HARNESS}-{TOPIC}.md`)
3. Run harness-integration-tracker skill to generate `INTEGRATION-SUMMARY.md`
4. Update this README with the new harness entry

### Keeping Integration Data Fresh

The `harness-integration-tracker` skill scans integration code and compares it with documented behavior:

- **Automated scanning**: Detects KNOWN_KEYS, KNOWN_MODELS from harness provider configs
- **Drift detection**: Highlights when docs don't match code reality
- **Version tracking**: Records breaking changes and new capabilities
- **Schedule**: Recommend running monthly or when framework code changes significantly

See `src/skills/harness-integration-tracker/SKILL.md` for full documentation.

## Integration Points

### Where Harness Code Lives

- **Harness configurations**: `config/*.yaml` (environment-specific)
- **Agent implementations**: `src/orchestration/agents/` (agent code for each harness)
- **Integration middleware**: `src/orchestration/` (queue, protocol, models)
- **Integration tests**: `tests/` (harness compatibility tests)

### Key Concepts

- **KNOWN_KEYS**: Required and optional configuration keys for a harness
- **KNOWN_MODELS**: Models tested and supported by a harness (e.g., Haiku, Sonnet, Opus)
- **KNOWN_VERSIONS**: Minimum harness versions required for framework compatibility
- **DRIFT**: Mismatch between documented capabilities and actual code

## Contributing

When modifying harness integration code:

1. Update relevant documentation in `docs/research/{harness}-docs/`
2. Run `harness-integration-tracker` skill to verify no drift
3. Update `INTEGRATION-SUMMARY.md` if adding new keys or models
4. Ensure integration tests pass
