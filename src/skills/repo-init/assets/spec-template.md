## 3. Agent Team

### Enabled Roles

| Role | Model | Effort | When to Use |
|------|-------|--------|-------------|
| **Orchestrator** | {senior_model} | low | Routes all tasks via queue |
| **Engineer** | {engineer_model} | low | Code implementation, bug fixes, routine tasks |
| **Senior Engineer** | {senior_model} | medium | Complex features, deep debugging, mentoring |
| **Lead Engineer** | {lead_model} | medium | Code review, standards enforcement |
| **Quality Engineer** | {senior_model} | medium | Testing, coverage, quality gates |
| **Security Engineer** | {principal_model} | medium | Security reviews, vulnerability analysis |
| **Principal Engineer** | {principal_model} | high | Architecture, organization-wide decisions |

### Routing Decision Tree

```
Task arrives in queue
│
├── Security concern?          → Security Engineer
├── Architecture decision?     → Principal Engineer
├── Code review?               → Lead Engineer
├── Quality gate / testing?    → Quality Engineer
├── Complex / cross-service?   → Senior Engineer
└── Standard implementation?   → Engineer
```

## 6. Delegation Protocol

### DELEGATE Block Format

All tasks MUST enter via a DELEGATE block:

```yaml
DELEGATE:
  task: <task-description>
  skill: <skill-name>           # Optional; omit for general agent work
  effort: low | medium | high
  model: <model-name>
  priority: priority | standard | future
  context: |
    <Additional context for the agent>
  acceptance_criteria:
    - Criterion 1
    - Criterion 2
```

### HANDBACK Block Format

All agents MUST return a HANDBACK block:

```yaml
HANDBACK:
  status: SUCCESS | FAILED | PARTIAL
  agent: <role>
  model: <model>
  effort: <effort>
  summary: |
    <What was done>
  deliverables:
    - path/to/file1.py
    - path/to/file2.md
  tests_passed: true | false
  coverage: <percentage>
  warnings: []
  errors: []
  next_steps: []
```

## 8. Conventions

### Naming Conventions

| Context | Convention | Example |
|---------|------------|---------|
| File names | `kebab-case` | `my-module.py` |
| Python identifiers | `snake_case` | `my_function()` |
| Python classes | `PascalCase` | `MyClass` |
| Test names | `test_<action>_<scenario>_<expected>` | `test_create_user_valid_returns_201` |
| Agent names | `kebab-case` | `senior-engineer` |
| Skill names | `kebab-case` | `usage-tracking` |
| Branch names | `feat/<description>` or `fix/<description>` | `feat/add-auth` |
| Commit messages | Imperative present tense | `Add user authentication` |

### Test Naming Format

Tests MUST follow: `test_<action>_<scenario>_<expected>`

```python
# ✅ Correct
def test_create_user_valid_returns_201():
def test_login_invalid_password_returns_401():
def test_analyze_repo_python_detects_language():

# ❌ Incorrect
def test_user_creation():
def testLogin():
```

### Commit Message Format

```
<type>(<scope>): <description>

Types: feat, fix, test, docs, refactor, chore, wip
Examples:
  feat(auth): Add JWT token refresh
  fix(api): Handle empty request body
  test(wip): Add RED-phase tests for user model
  docs: Update ONBOARDING.md
```
